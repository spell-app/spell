On the plane, you mark items, comment and add new epics in VS Code's side bar, and every click saves on the laptop. On the ground, /airplane land gathers it all and works through it in the background.

Airplane mode is how you work on the epics and docs with no Claude (a plane, bad wifi), and how Claude takes what you left once you're back. Most days a mark goes straight to a session that answers it; here it waits in an inbox on this laptop until the landing.

The steps: the /airplane skill; its commands, epic airplane --help How an epic page works, and how to review one: Epic Pages, a Tour Written for: you before and after a flight, and any agent running the landing Checked: 2026-11-21, every command and file against that day's code
  • Everything you do on a page saves to this laptop's page server: no internet, no Claude.
  • /airplane before the flight:
    • checks the laptop is ready and fixes what it can (epic airplane check --fix)
    • asks which running sessions to /park: a session mid-work stalls offline
    • asks, every time, whether to run /docs-check on the epics merged since the last flight
    • turns airplane mode on (epic airplane on)
  • On the plane, in VS Code's side bar:
    • read any epic page or guide
    • mark items, note a phase or the summary
    • comment on any block or selected text
    • add new todos, questions and epics
  • /airplane land after: gathers everything you left, by place, brings the parked sessions back, and works through it in the background. Then /epic review for what came back.

The side bar shows the MAIN checkout's page server, so /airplane runs its commands there, from whichever session you type it in, a worktree's too.

  • Its extension check rebuilds the VS Code extension when it's older than the code.
  • Then reload the window once (Developer: Reload Window).

What makes the pages work with no internet and no Claude, and what they look like while they wait: toolbars, the header, the side bar, comment threads.

  • Docs pages once loaded their code highlighter (highlight.js) from the internet, and waited for it. On a hanging network, a page showed raw markup for tens of seconds.
  • The epic plugin has its own copy, highlight.min.js, served at /_epic/assets/highlight.min.js.
  • The page server points each page still naming the internet copy at the local one, as it serves it (its localCopies setting): no page changes on disk.
  • New pages load the local copy from the start: the templates do.
  • epic pages offline lists anything a page still fetches from the internet; with --fix, it points the old tags at the local copy. /airplane's check runs it.
  • One switch per machine, in a small file: ~/.spell/airplane.json (read and written by AirplaneMode).
  • epic airplane on | off | status flips and reads it; check and inbox are the skill's before and after.
  • The page server tells each page whether it's on, as it serves the page (SPELL_SERVER.airplane).
  • With it on, an epic page's review line says "Airplane mode: what you mark here waits for /airplane land", and its pill "Airplane mode: this waits for /airplane land", where they'd say "No Claude session is reviewing".
  • /airplane asks, every time, whether to run /docs-check first, on the epics merged since the last flight. Its fixes wait in Source Control to review on the plane.
  • The summary takes Make Todo and Revisit, as Overview sections do (no Approve); a phase takes Revisit, beside its Do this or Accept plan.
  • A new item is a mark of its own kind in the inbox (action: "new"), keyed new1, new2 ...
  • It shows dashed at the end of its section until it's applied.
  • epic inbox apply <name> makes the items, as epic add does.
  • With --all, it also takes marks never sent.

What you do:

  • Starts one with the bullhorn beside a block (sections, tables, asides, code, items, phase fields), or ⌘ I on selected text, which keeps the quote and highlights it softly.
  • Writes it in a small floating pane, just under the selection:
    • drag it by its header; the page never scrolls
    • it saves as you type: the floppy shows saved, or turns red
    • Tab or a click elsewhere saves it; × or Escape closes it
    • never an empty comment: nothing typed saves nothing, and emptied, it goes
  • Reads it after as a THREAD: one ivory pane under the paragraph the quote is in.
    • each message starts with a bold You: or Claude:, its time at the top right
    • while it's your turn: the item's pills, ✓ (that's good), Revisit (reply) and × (skip it)
    • a reply box at the end of every open thread
    • Done folds it, with Undo; a closed thread shows Reopen
  • Deletes one with one click on the trash; Undo in the toast brings it back for 6 seconds.
  • Send hands over waiting comments and replies, as it does marks.

What Claude does:

  • Finds them where they wait, on this laptop, git-ignored:
    • a docs page's in <page>.inbox.json5, beside it
    • an epic page's in the epic's review inbox (ids C1, C2 ...)
  • Marks one it's thinking about: the thread shows "Claude: thinking…" until its answer replaces it.
    • docs pages: epic comments working <page>#C3 on
    • epic pages: epic inbox working <name>#C3 on
  • Answers on the thread:
    • docs pages: epic comments answer <page>#C3 --file <answer.html>
    • epic pages: epic inbox done <name>#C3 --file <answer.html>
  • Or, at the landing, epic comments gather puts each docs page's comments into the standing epic feedback, one phase per page.
  • A docs page an epic owns is left out of that: its comments go to that epic, with the page header's Send, and its session answers them, as an epic page's.
  • Comments replaced the older page notes. Notes already written still show, read only, and epic notes still answers them.
  • Every docs page has a sticky toolbar under its title, edge to edge, with a rule below and none above.
    • a guide's: a button per top-level section, titles shrinking to fit
    • an epic page's: a round icon per section, with a red, orange or blue badge counting what waits; on its right, the state chips, collapse-all and the new-item button
  • The epic page's header is one line:
    • the epic's title, cut short when narrow
    • Send in its middle, while the page is reviewed, with Auto Send's countdown ring round it
    • at its right, the step label, carrying the epic's state (its icon and colour, why in its tooltip), then the gear: Auto Send and Theme
  • Under it, the review line, and the pill while nobody is reviewing (or the airplane one). A click copies its command; out of airplane mode it also starts the review in the epic's own session.
  • An item folds once you pick its action, animated (300ms, as sections do); none under reduced motion.
  • No jumping: a fold, a click on a line or a link's landing never moves the page.
  • Narrow (VS Code's side bar), the site header shows the breadcrumb instead of its tabs, and the page starts right under it.
  • The side bar has three tabs, Review, Details and Epic Docs, each holding one live page.
  • VS Code's keys work from inside a page there: ⌘ ⇧ P, ⌘ P, ⌘ B, ⌘ W, F1 ...
    • the page's own keys stay its own: ⌘ A / C / X / V / Z / F, ⌘ K, ⌘ I
  • Right-click shows VS Code's menu: Cut / Copy / Paste / Select All, Back / Forward / Reload, Open in Browser, Inspect (Developer Tools).
  • Each tab's title bar has Back, Forward, Reload, Restart Page Server and Open in Browser.
  • A judgement call or issue Claude records is yellow (calm) unless it would surprise you or go against what you said: then red.
  • So the red badges in the toolbar are only what needs you.
  • epic calm <name>#<id> ... calms items already written; --loud makes them urgent again.
  • Inboxes and comments live on this laptop only, until the landing takes them.
  • A new worktree on the plane needs yarn install: it ran in offline mode on an installed worktree, never on a fresh one.
  • The new-item form keeps no draft: a reload while typing loses it.
  • Old marks get taken too: an inbox can't tell a mark made on the plane from one left earlier. /airplane's waiting line lists them before the flight.
  • Not yet tried: the landing's background half on a real backlog. Expect to steer the first one.
  • Untested by hand yet: the floating bullhorn on selected text, clicking a quote, clearing a comment.
