<epic-aside> The <epic-aside> element: a folded aside, a digression the main text can skip.

A folded aside in prose: a digression the main text can skip. It draws an ivory panel headed "Aside: <title>"; the aside is its children.

For anyone reading or writing an epic page's markup, or changing this element.
Its vocabulary (every name it uses): EpicAside.en.ts.
Its component: EpicAside.tsx, with its style sheet (.css) and tests beside it.

A real one, from epic docs-workspace (O3). Click its heading to unfold it.

Ids, icons, UPDATE markers and the "updated" stamp must agree across the phase list, the phase sections and the items. Agents editing by hand drift; the script also locks the file so parallel agents take turns.

Live: the real element, drawn by the epics pack this page loads.

A page's own buttons go in its title row: <ui-button slot="actions"> children (epic epic-workflow P25).

  • They sit at the right of the title row, after the heading. The heading is its fold button, and it ends where they start.
  • A click on one never folds or unfolds it.
  • The docs runtime puts the block's bullhorn there too, so it never sits over a button.

A button floated over the heading's corner sat on the fold button; in the row, each has its own room.

Its parents:

  • Anywhere prose goes: it's a prose element:
    • <epic-item>: among an item's own text, before its cards
    • <epic-answer>, <epic-more>, <epic-reply>: the cards under an item
    • <epic-option>: an option card's pros and cons
    • <epic-field>: a phase's field, or a labelled block
    • <epic-updated>: a change to a phase's plan
    • <epic-section>: an Overview sub-section's prose, or a report's
    • <epic-version>: an earlier version, kept as it was
    • another prose element (a note inside an aside), or plain HTML around it (a <li>, a <div>)

A slot is where the element's own children show.

Slot Holds
(default) The aside.
actions Buttons of the page's own in its title row (<ui-button slot="actions">): after the title, before its own buttons; a click on one never folds it. The docs runtime puts the block's bullhorn here too.

A part is a piece of the drawing a page's CSS can reach.

Part Is
base The panel.
head Its title row: toggle, then actions.
toggle Its heading, a <button> that folds it: the chevron, then heading.
heading The heading's words.
body What it folds; hidden (until-found) while folded.
actions In its title row, after the title and before its own buttons: the actions slot.

A state is set by the element on itself; none is ever written in the doc.

State When
open Unfolded: the reader opened it.
  • Its heading: always in full, as many lines as it needs, folded or open. The chevron and the slot's buttons sit on its first line, so nothing moves as it folds (Owen, 2026-10-19).
  • The brand's ivory panel, as the docs' asides (ui-accordion.spell-aside): warm, rounded, no border (--epic-aside from <epic-page>, with a fallback).
  • Its heading in the headings' italic serif, so it reads as an aside, not a section. Its text a step smaller than the page's.
  • No state colour: the ivory is the panel's, not a meaning.
  • Folded to start with. A click on the heading, or find-in-page, unfolds it; folding is the page's, never written.
  • It shares its shape with <epic-code> (EpicPanel, in the same family folder).
  • Claude writes it inside the HTML it passes to epic (add ... --details, decide --details, details --file, updated): no command makes one by itself.
  • The epic tool turns the OLD hand-shaped markup into this element, so a doc never holds the old shape.
    • It does this in any HTML a command takes: add --details, decide --details, details --file, updated.
    • The code that does it: IncomingHtml and ProseRewrite.
    • Prose edited by hand in a part file isn't passed through it.
    • The old shape: ui-accordion.spell-aside.
  • The converter did the same to every converted doc (ProseUpgrader).
