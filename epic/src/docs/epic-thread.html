<epic-thread> The <epic-thread> element: one comment's whole thread on a page, as the docs runtime's comments draw it.

One comment's whole thread: its header (the bullhorn, its id, the first words it's on), Owen's answer while it's his turn, the messages in order, then his reply box. The docs runtime's comments draw one under the paragraph, list item or cell holding a comment's quote, else under its block, on every page that takes comments: a guide, an epic page, an Epic UI page.

For anyone changing how comments look or work on a page.
Its vocabulary (every name it uses): EpicThread.en.ts.
Its component: EpicThread.tsx, with its style sheet (.css) and tests beside it.

Every state a thread is in, from what the comments route answers (the comments are made up):

  • C1: new, Claude's turn, folded: the pen (his words wait, Claude hasn't had them) and the trash.
  • C2: Claude thinking about it: the stub his answer replaces.
  • C3: Owen's turn, orange: the review pills, That's good, Reply, Skip it.
  • C4: done: a check circle, Reopen, and the green Done line inside.
  • C5: taken into an epic's phase, linked by the phase's stable id.

Live: the real elements, drawn by the epics pack this page loads. Their buttons say what Owen did (their events); only the comments' code saves, so here they fold and nothing more.

Never written in a page: the comments' code (PageComments.thread()) makes one per comment and keeps it for the visit, giving it what the server holds at each redraw. In markup, for a page like this one:

Its id, comment-c3, is what Cmd / Ctrl + K and the toolbar's bullhorn land on.
  • Its parent: <epic-threads>, the box of threads under one block.
  • Its child: Owen's box, a <textarea> the comments' code makes and keeps: the reply box, or the pen's box over his first words.
  • In its shadow root: each message, an <epic-thread-message>, and Owen's answer, an <epic-review buttons="thread"> (the item's review pills).
