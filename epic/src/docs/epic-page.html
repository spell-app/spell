<epic-page> The <epic-page> element: a whole epic page, one epic's page.

<epic-page> is a whole epic page: one epic's page.

  • Its attributes hold the epic's data (name, title, branch, dates); its children are the Overview and the sections.
  • It draws everything above them: the breadcrumbs, the sticky page header, the meta lines, and the review buttons.

Written for: anyone reading or writing an epic page's markup, or changing this element.
Status: built in epic-page/.
Its vocabulary (attributes, slots, parts, children): EpicPage.en.ts.
The component: EpicPage.tsx.

As markup only, not drawn live: the note below says why.

An <epic-page> takes over the page around it: its header sticks under the site header, and its sections join the page's rail. So it shows only as markup here; to see one drawn, open this epic's own epic page.

  • no Send: it shows only while an epic page is being reviewed through the page server

An epic page's page · 24 lines
  • <ui-root> loads the epics pack, the script that defines every <epic-*> tag, from its <ui-components source>.
  • The file's <title> reads Epic: <title>; the page's title holds the title alone.
  • None of the header is written in the file: the element draws it from the attributes and the phases below.

None: it's the page. An epic page's file holds exactly one, in main.spell-doc-main, inside <ui-root>.

The Overview first, then the sections, each kind once at most, with its fixed id. A report (kind="report") is the one section that isn't numbered: it sits right after the Overview.

In THIS order, always: the tool puts each child where it belongs, and the check refuses another order.

Part What it is
base The page.
crumbs In the h1, before the epic's name: Docs / Epics /, the docs' eyebrow. None narrow, nor while the doc still holds its old ui-breadcrumbs.spell-crumbs before the page.
header The sticky page header: the h1, then the tools and labels at its right.
heading The h1: the crumbs, then the epic's name in their type, twice their size and bold; a click on the name copies /epic resume <name>.
actions While the page is reviewed: Send (<epic-send-buttons>: the paper plane grey, blue with unsent marks, outlined once sent; no wand since 2026-10-25).
send Send, an <epic-send-buttons>: every unsent mark and comment to Claude, on a press (epic epic-engine P20; its wand and countdown gone since Owen, 2026-10-25).
git The git toggle: shows or hides every commit (only when the doc has some).
status The state mark (in progress, errors or paused), then the bedtime and step labels.
state The epic's state, an icon in its colour: in progress (blue), errors (red: every phase done, items need you), paused (grey: phases left, untouched for days); why on hover. None for a future epic or a done one: the step label says so.
review-line Under the header: To review this doc, type /epic review <name>, copied on click; while the page is reviewed with nobody listening, it says no session is reviewing.
pill Under the review line, while work waits and nobody listens (orange), or in airplane mode: no session is reviewing, or what the page server's wake did ("Typed /epic review <name> into 🚧 <name>: press Enter there"). A click types the command into the epic's session.
meta The meta lines: branch, worktree, dates, saga, guide.
see-also Above the blocks: the pages the epic made or leans on (its guide, its details/ folder, the guides it links), each a link with its kind (an li[data-kind]), gathered by the page server's GET /api/epics/pages. None, no box.
notice A future epic's notice: not planned yet.
hung A doc still planning (no phases, not future): the folded Plan hung? aside, with the prompt to copy.

With kind="saga" it's a SAGA page (epic epic-workflow P15): one saga's page, sagas/<id>/<id>.saga.html, built of the same elements, so its items, marks, comments and Send work as an epic page's.

  • Crumbs DOCS / SAGAS / <ID>; a click on the id copies its review command.
  • One meta line, its short address (SAGA:/drawable-spell, copied on click), then its dates.
  • No step label, state, Plan hung?, See Also or Agents running: a saga has no phases or branch.
  • Send and the review line as on an epic page. Its marks and comments wait in its own inbox, beside it, for the session running /epic review SAGA:/<id>.
  • Its sections: the Overview (the saga's purpose, Done so far, Ideas not done yet), Epics (<epic-cards>), Questions, Todos, Log.
  • Made by epic saga page <id> from the tool's saga.html; every epic verb edits it as SAGA:/<id>.
A saga page's markup · 13 lines

A page goes through three stages (epic epic-engine P29): the Overview is agreed first, then the phases, then it's built. Its stage says which, and decides what the page shows.

Stage What shows The header's button An open phase's pills
overview the Overview, Questions, Todos Accept Overview (no phases show)
phases the Phases too Accept Phases Looks good, Defer
building, or none everything Send (the paper plane) Make Todo, Revisit
  • Hiding is only a view: the file still holds every section, and the toolbar lists only what shows. The sections are numbered as they show (2. Questions while the Overview is agreed).
  • The button sits where Send's paper plane does. Its tooltip counts the open questions ("2 questions open"): a reminder, never a lock.
  • A press sends what's unsent with an accept mark. The session's epic inbox apply moves the page on a stage, then writes the phases (after the Overview) or starts building (after the phases). Pressed, the button is outlined green until then.
  • Building, while Claude's build plan for a phase waits for Owen's Accept, the header keeps Send, never green (Owen, 2026-10-25: "I may not be accepting the phases"): the pill is RINGED, its border 2px #666, darker than its hairline, waiting on him, dotted once each waiting phase has his mark; its tooltip names them, "2 build plans wait for your Accept: P43, P44". Accepting is per phase, on its row, whose buttons wear the same ring.
  • Defer moves a phase after the others, still to do; Looks good says it stands as written. Both wait for Send, as every pill does.
  • epic create starts a new epic in overview, a future one too; epic stage <epic> overview|phases|building sets it by hand.
