<epic-run> The <epic-run> element: a run page's body: a command asks, Owen answers each row, Send.

A run page's body: a command stopped to ask Owen, and waits for his answers.

For anyone writing a command that asks Owen on a page, or changing this element.
built in epic-run/ (epic epic-engine P23).
Its vocabulary (every name it uses): EpicRun.en.ts.
Its component: EpicRun.tsx, with its style sheet (.css) and tests beside it.

No live example here: it draws a RUN, which only a command makes, and reads it from the page server (GET /api/runs/<id>). A run's page is /runs/<id>/.

What Owen sees there, top to bottom:

  • the page's title (the run's), then who is waiting: spell translate todos --to es is waiting, with a green dot; or why nobody is (it finished, it stopped, its wait ran out, it isn't running)
  • the status card (epic epic-engine P25), when the command writes passes or offers an effort: the effort picker (fast | balanced | best, saved at once, taking effect at the next pass), then a line per pass, with its name, 212 of 380, its calls and its time; only the running pass has a bar, and its time ticks on by the second
  • the command's line about what it asks, and its latest progress line; every line, folded (with a status card, only the fold)
  • the table: the command's columns, then the answer's; a row per thing to answer, each an <epic-run-row>
  • the Send bar, stuck to the window's bottom: 3 of 5 answered · not sent, the last save, and Send, with no countdown: a command carries on with exactly what you sent

Once a page, in the run page's template; the route module sets its run:

run.html · the run's body · 1 line
  • Its parent: a run page's main, under the sticky page header, from the template (spell-epic's run.html).
  • Its children: none. It draws its rows, <epic-run-row>, in its shadow root.
  • Its run: the epic folder's pages/runs/<id>/, written by the kit's SRV.CommandRun; served and answered by spell-epic's runRoutes.ts.
Name Values Meaning Required
run a run's id ([a-z0-9-]) The run to draw: its folder's name in pages/runs/. yes
  • Who is waiting: muted; the command in mono, a green dot before it while it waits.
  • The status card: a quiet rounded box. The effort a pill track, the chosen one a raised thumb; disabled once the run is over. The passes on one grid: the running one in full ink with a blue dot and bar, the done ones muted with a green check.
  • The table: a grid in a rounded box, its heads on a faint band; the answer's column the widest.
  • Too narrow for its columns (a phone): the table scrolls sideways inside its own box, never stacked.
  • Send: blue by the fill rule (dashed: not sent, or changes since; outlined: sent), the line before it green once sent.
  • A failed read, save or Send: red, bold, under the bar. A failed save tries again every 3s.
  • Nobody writes it: the run page's template holds it, and the route module serves that at /runs/<id>/.
  • A command opens a run with the kit's SRV.CommandRun.open(), shows it with show() (epic pages open <run folder> --review), and waits with wait().
