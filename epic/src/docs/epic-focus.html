<epic-focus> The <epic-focus> element: Focus mode, a full-screen overlay that walks an epic page's open items one at a time.

<epic-focus> is Focus mode: a full-screen overlay over an epic page that shows its open items one at a time, so you make a call on each without scrolling the whole page.

  • Open it from the epic page header's gear, "Focus mode", while the page is reviewed.
  • It walks the items the page draws red, orange, blue or yellow. Done, decided and grey ones never show.
  • Each item's buttons are the page's own: the same marks, the same Send.

For anyone changing how an epic page is reviewed.
Status: built (epic epic-engine P57), in the epic-focus family.
Its vocabulary: EpicFocus.en.ts
Its component: EpicFocus.tsx.

Live, on a few sample items. On an epic page it walks the page's own sections; here, for names the box holding them. Escape or × closes it. The buttons mark nothing here: this page has no review inbox.

It opens on the Phases tab (one plan waiting), then Questions (two: the decided one left out), then Issues. ← and → step through them; the last of a tab goes on to the next tab.

Nobody writes it in a doc: <epic-page> draws it in its shadow root while the page is reviewed, and opens it from its gear. No migration: nothing in a page's markup changes.

The Manual tests section's Start testing opens it too, on the Tests tab, once Claude has put the tests in order (epic epic-engine Q65): the section asks with epic-focus-asked, which the page hears.

  • Which items: by the page's own colour for each, the ONE rule its chips use (DrawnState for an item, PhaseState for a phase): red, orange, blue and yellow, and a phase's dotted blue. A todo that's a limit isn't walked.
  • Tabs: one per kind with any, by the id's letter, in this order: Phases, Questions, Todos, Calls (judgement calls), Issues, Tests. Each with its count, coloured by its most pressing item.
  • Order: the page's, but the Tests tab's: Claude's order (prepared ones first, deferred last).
  • Chips: the section's own <epic-state-filter>, one per tab, the same click rule (⌥-click for only that colour). Each tab's choice is its own, kept in this browser apart from the sections'.
  • The item: its id chip, title and whole text, COPIED from the page (a split page's part file, by the same fetch the page uses): the page's own item never moves. A link in it closes the overlay and lands on the page.
  • Its buttons: an <epic-review> with the page's kind for it (a question's, a todo's, a waiting plan's ...), and its note box, on the page's one review client.
  • Back and Next, and ← / →: a press keeps you on the item, so you see it marked. An item Claude closes while you're on it stays until you move on.
  • Keeps its place (open, tab, item, chips) across reloads, as the page keeps its folds.
  • Send: the overlay covers the page header, so while it's open the page's Send, and its countdown, ride in the overlay's top bar.
