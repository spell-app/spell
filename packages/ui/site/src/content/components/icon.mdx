<Section title="Behaviour">
  `name` is the only thing an icon needs.  It accepts Font Awesome names, and Fomantic's spellings as aliases:  a
  trailing `outline` word means the regular set, and `variant` picks a set (`regular`, `brands`) explicitly.

  Icons also work as the `icon` attribute of other components (`<ui-button icon="download">`), where they share this
  name resolution.  Icons have no events.

  <VocabularyTable family="icon" />
</Section>

<Section title="Theming">
  Theme with the public `--ui-icon-*` tokens.  Size tokens (`--ui-icon-size-huge` ...) rescale a whole step;  the
  glyph itself takes `currentColor`, so `color` on the icon or its parent works too.

  <CssTokens family="icon" />
</Section>

<Section title="Accessibility">
  - An icon is decorative by default:  `aria-hidden="true"` on the host, so screen readers skip it.
  - Give a meaningful icon a `label`:  the host becomes `role="img"` with that `aria-label`.
  - An icon that is the only content of a control (`<ui-button icon="cloud">`) needs the name on the control, not the icon.
  - `link` is only the look:  wrap the icon in a real `<a>` or `<button>` for interaction.
  - Without JavaScript the native fallback keeps the box (size, colour, ring), the `role` and the `label`, but not the glyph:  the SVG needs the icon data.
</Section>
