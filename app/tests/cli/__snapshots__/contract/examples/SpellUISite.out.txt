it"><ui-markdown>Write `&lt;ui-button&gt;` with its text inside, and add attributes for the look.

Most attributes become Fomantic's class words, on the real button in the shadow root:
`&lt;ui-button size="small" color="primary" appearance="basic"&gt;` draws `ui small basic primary button`.

- A boolean attribute is true when it's there, or empty.
  `"true"` and `"yes"` mean true too;  `"false"` and `"no"` mean false.
- `medium` is a real size meaning "default":  it draws no class.
- Three attributes stand in for slots, and children in the slot win:
  - `icon` for the `icon` slot
  - `label` for the default slot (`content` is its old name)
  - `badge` for the `label` slot:  the joined badge
- `link` draws an `&lt;a&gt;` in place of the button, so it navigates like a link.
- Wrap buttons in `&lt;ui-buttons&gt;` to join them.
  The group's words (`size`, `color` ...) reach every button in it.</ui-markdown></ui-section><ui-section label="Events"><ui-markdown>A plain click is the native `click`.
A toggle button also sends `ui-selected` as it turns on, and `ui-deselected` as it turns off.
Both carry the new state in `event.detail.active`.</ui-markdown><ui-markdown>```js
const toggle = document.querySelector("ui-button[toggle]")
toggle.addEventListener("ui-selected", () =&gt; console.log("on"))
toggle.addEventListener("ui-deselected", () =&gt; console.log("off"))
```</ui-markdown></ui-section><ui-section label="State texts"><ui-markdown>Fomantic's `state` behaviour is two attributes on a toggle button here, not a module of its own:

- `inactive-text` replaces the content while the button is off.
- `active-text` replaces it while the button is on (`selected`).
- With only one of them, the button's own content shows in the other state.

They're live on the Examples tab, under [State texts](/edit/@spell/notebooks/Button/Examples.spellml#states-state-texts).

The label SAYS the state, so a toggle button with a state text leaves `aria-pressed` off.
A toggle button whose name changes would announce the state twice (WAI-ARIA APG).
Listen for `ui-selected` and `ui-deselected` as usual.</ui-markdown><ui-markdown>```js
const follow = document.querySelector("ui-button[active-text]")
follow.addEventListener("ui-selected", () =&gt; startFollowing())
follow.addEventListener("ui-deselected", () =&gt; stopFollowing())
```</ui-markdown></ui-section><ui-section label="Invoker commands"><ui-markdown>A `&lt;ui-button&gt;` drives other elements with no script, as a native button does:

- `commandfor` is the target's id, looked up in the button's own tree.
- `command` is the action.

The actions:

- A `&lt;dialog&gt;` and a popover take the browser's own commands.
- A custom command's name starts with two dashes.
  It reaches the target as a `command` event.
- `&lt;ui-modal&gt;` answers three custom commands.

```text
&lt;dialog&gt;
  show-modal, close, request-close
a popover
  show-popover, hide-popover,
  toggle-popover
&lt;ui-modal&gt;
  --show, --close, --toggle
```

The button inside the shadow root can't see a light-DOM id,
so the element hands it the target itself (`commandForElement`).
In a browser without invoker commands (`UI.browser.supports.invokers`),
a click runs the built-in commands itself.</ui-markdown><ui-section collapsible="" dividing="" label="Popup and modal" sticky=""><spell-example description="A button opens a popup and a modal with `commandfor` and `command`, no script." name="Popup and modal"><ui-button command="toggle-popover" commandfor="button-invoker-popup">Toggle popup</ui-button><ui-popup id="button-invoker-popup" label="Toggled by the button, no script." open-on="manual"></ui-popup><ui-button color="primary" command="--show" commandfor="button-invoker-modal">Open modal</ui-button><ui-modal closable="" content="Opened by a ui-button." heading="Invoked" id="button-invoker-modal"></ui-modal></spell-example></ui-section></ui-section><ui-section label="Forms"><ui-markdown>A `&lt;ui-button&gt;` is a form-associated element, so it works inside a `&lt;form&gt;` like a native button.

- `type` is `button` by default, so a plain one never submits by accident.
- `type="submit"` submits the form round it with `form.requestSubmit()`,
  so validation and the submit event run.
  `type="reset"` resets it.
- `name` / `value` are submitted with the form when this button submits it.
- `button.click()` from a script presses it as a click would:  it submits, toggles or follows its link.
  So Enter in a `&lt;ui-input&gt;` submits through the form's submit button.
- A disabled `&lt;fieldset&gt;` disables the buttons inside it.
- To submit, the buttons need a real `&lt;form&gt;` in the light DOM:  inside a `&lt;ui-form&gt;` too.</ui-markdown><ui-markdown>```html
&lt;ui-form&gt;
  &lt;form action="/subscribe"&gt;
    &lt;ui-input name="email" type="email" required&gt;&lt;/ui-input&gt;
    &lt;ui-button type="submit" name="action" value="subscribe" color="primary"&gt;Subscribe&lt;/ui-button&gt;
    &lt;ui-button type="reset" appearance="basic"&gt;Reset&lt;/ui-button&gt;
  &lt;/form&gt;
&lt;/ui-form&gt;
```</ui-markdown></ui-section><ui-section label="Keyboard"><ui-markdown>The shadow root holds a real `&lt;button&gt;` (or `&lt;a&gt;`), so the browser does the keyboard work.

- **Tab** / **Shift+Tab** moves focus to and from the button. The host delegates focus
  (`delegatesFocus`), so it is never a tab stop of its own and the focus ring is drawn on the inner
  control.
- **Enter** or **Space** clicks a button; **Enter** follows a `link`.
- A toggle button flips `selected` on **Enter** or **Space**, as a click does.
- A `disabled` button is skipped by **Tab**.</ui-markdown></ui-section><ui-section label="Accessibility"><ui-markdown>- Focus, **Enter** and **Space**, form submission and the accessible name
  all come from the browser's own `&lt;button&gt;`;  with `link`, from its `&lt;a&gt;`.
- An icon-only button needs a name:  put `aria-label` on the element.
  It forwards it to the inner button, and shows it as the button's tooltip.
- A toggle button sets `aria-pressed`, and keeps it in step with `selected`.
  Not with a state text:  see [State texts](#state-texts).
- `loading` sets `aria-busy`.
  `disabled` disables the inner button.
- `&lt;ui-buttons&gt;` has the group role:  give it an `aria-label` when the group needs a name.
- If the element fails to render, its native fallback keeps a plain `&lt;button&gt;` styled by the same
  class words, so the button still renders, focuses and submits its form.</ui-markdown></ui-section><ui-section label="Framework usage"><ui-markdown>Define the elements first (load the bundle, or `&lt;ui-root&gt;`), then use the tag like any other. Events
are `ui-*`, so use your framework's custom-event syntax.</ui-markdown><ui-header id="framework-react" level="4">React 19</ui-header><ui-markdown>```jsx
&lt;ui-button toggle onui-selected={() =&gt; setOn(true)} onui-deselected={() =&gt; setOn(false)} color="primary"&gt;Vote&lt;/ui-button&gt;
```</ui-markdown><ui-header id="framework-vue" level="4">Vue 3.5</ui-header><ui-markdown>```html
&lt;!-- compilerOptions.isCustomElement = (tag) =&gt; tag.startsWith("ui-") --&gt;

```</ui-markdown><ui-header id="framework-solid" level="4">Solid 2</ui-header><ui-markdown>```jsx
// events and rich data are plain props:  `on-&lt;event&gt;={...}`, `options={...}`

  Vote
&lt;/ui-button&gt;
```</ui-markdown></ui-section></test-project-button-usage></div></div></div></test-project-spell-ui></div>
