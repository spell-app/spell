==== /HowTaskListWorks.spell
⟪## How the Task List works⟫
⟦// The Task List example is a to-do list:  type a task and add it, tick it off when it's done,⟧
⟦// delete it, and drag the tasks into another order.⟧
⟦// Four ideas do the work:⟧
⟦// - each task is a THING of its own, which draws itself as a row:  a box to tick, its title, a button⟧
⟦// - the new task's field is a form bound to the app:  Add makes a task from what's typed⟧
⟦// - the count picks tasks out with "where":  "tasks in the checklist where it is active"⟧
⟦// - one line lets the list's tasks be dragged into another order⟧
⟦//⟧
⟦// This guide keeps those four, and leaves out where the tasks are kept:⟧
⟦// here they're in memory, and start afresh each run.⟧
⟦// Open Task List, from Make something on the home page, for all of it.⟧


⟪## A task⟫
[thing create_type L0]
| a «"task"» is a **draggable view**
|   [property define_property_has L1]
|   | its «"title"» is **text**
|   [property define_property_has L1]
|   | its «"done"» is yes or no
|   [property quoted_type_expression L1]
|   | it «"is done"» if its **done** is _yes_    ‾value(its done)
|   [property quoted_type_expression L1]
|   | it «"is active"» if it is not done    ‾question(it is not done)


⟪## The checklist:  the tasks, one under the other⟫
[thing create_viewable_list_type L0]
| a «"checklist"» is a **viewable list of tasks**
|   its items can be reordered immediately
|     ⟦// its tasks can be dragged to another place⟧
|   [action to_do_something L1]
|   | to **draw** it
|   |   <⟨stack⟩ spacing=«"xs"»>
|   |     <⟨children⟩ />
|   |   </⟨stack⟩>
[property belongs_to_one L0]
| a **task** belongs to one **checklist**
|   ⟦// so a task knows its checklist, to leave it⟧


⟪## How a task draws⟫
[thing reopen_type L0]
| a **task**
|   [action to_do_something L1]
|   | to «"delete"» with title «"Delete"», icon «"trash alternate outline"»
|   |   remove it from its **checklist**    ‾value(it) ‾value(its checklist)

|   [action to_do_something L1]
|   | to **draw** it
|   |   ⟦// a form of its own, bound to the task:  ticking the box changes its "done"⟧
|   |   <⟨form⟩ value={it}>    code({it})
|   |     <⟨stack⟩ direction=«"horizontal"» spacing=«"sm"»>
|   |       <⟨checkbox⟩ name=«"done"» aria-label=«"Done"» />
|   |       <⟨input⟩ name=«"title"» aria-label=«"Task"» appearance=«"transparent"» fluid />
|   |       <⟨action⟩ «"delete"» icon-only appearance=«"tertiary"» />
|   |     </⟨stack⟩>
|   |   </⟨form⟩>


⟪## The app⟫
[thing create_one_of_a_kind L0]
| «task list» is an **app**
|   [property define_property_has L1]
|   | «"checklist"» is **a new checklist**
|   [property define_property_has L1]
|   | its «"draft"» is **text**
|   |   ⟦// the next task's title, as the new task's field holds it⟧
|   [property property_value_getter L1]
|   | its «"active count"» is the **length** of (**tasks** in the **checklist** where it is active)
|   |   ⟦// how many are left:  the tasks picked out with "where", counted⟧

|   [action to_do_something L1]
|   | to «add the draft»
|   |   ⟦// a new task at the end of the list;  the field empties⟧
|   |   if the **draft** is _""_ return    ‾value(the draft)
|   |   add (**a new task** with **title** = the **draft**) to the **checklist**    ‾value(a new task with title = the draft) ‾value(the checklist)
|   |   clear the **draft**    ‾value(the draft)

|   [action to_do_something L1]
|   | to **draw** it
|   |   <⟨container⟩>
|   |     <⟨stack⟩>
|   |       <⟨text⟩ color=«"grey"»>{the **active count**} to do</⟨text⟩>    code({the active count})
|   |       <⟨form⟩ value={it}>    code({it})
|   |         <⟨input⟩ name=«"draft"» placeholder=«"Something to do"» aria-label=«"New task"» fluid action>
|   |           <⟨button⟩ slot=«"action"» color=«"primary"» disabled={the **draft** is _""_} onClick={add the draft}>Add</⟨button⟩>    code({the draft is ""}) code({add the draft})
|   |         </⟨input⟩>
|   |       </⟨form⟩>
|   |       {draw the **checklist**}
|   |     </⟨stack⟩>
|   |   </⟨container⟩>


⟪## Start:  three tasks, one of them done⟫
add (**a new task** with **title** = _"Read this guide"_, **done** = _yes_) to the **checklist** of the **task list**    ‾value(a new task with title = "Read this guide", done = yes) ‾value(the checklist of the task list)
add (**a new task** with **title** = _"Tick a box on the right"_) to the **checklist** of the **task list**    ‾value(a new task with title = "Tick a box on the right") ‾value(the checklist of the task list)
add (**a new task** with **title** = _"Drag a task to the top"_) to the **checklist** of the **task list**    ‾value(a new task with title = "Drag a task to the top") ‾value(the checklist of the task list)


⟪## A check⟫
[action to_do_something L0]
| to «test counting the tasks to do»
|   set the **list** to **a new checklist**    ‾value(the list) ‾value(a new checklist)
|   add (**a new task** with **title** = _"a"_, **done** = _yes_) to the **list**    ‾value(a new task with title = "a", done = yes) ‾value(the list)
|   add (**a new task** with **title** = _"b"_) to the **list**    ‾value(a new task with title = "b") ‾value(the list)
|   the **length** of (**tasks** in the **list** where it is active) should be _1_    ‾value(the length of (tasks in the list where it is active))

⟪## Where the example keeps its tasks⟫
⟦// This guide's tasks live in memory:  reload, and they start again.⟧
⟦// Task List keeps them on this device, in the browser's own storage:  reload, and they're still there.⟧
⟦// No server is asked, and there's no sign-in.  Two lines, in its API file, say so:⟧
⟦//       my tasks is stored on this device⟧
⟦//       a task lives in my tasks⟧
⟦// After them, the words you already know reach the device:⟧
⟦//       for task in (every task) sorted by its order⟧
⟦//       add task to the tasks⟧
⟦//       remove it from the tasks⟧
⟦// A task kept there saves itself as it changes:  ticking it, or typing its title, is kept, with no save step.⟧
⟦// Its place in the list is kept the same way, as its "order":  a drop sets each task's order to its place,⟧
⟦//       - when a task is dropped on it:⟧
⟦//           keep the order⟧
⟦// so the tasks come back in the order they were dragged into.⟧
⟦// Keeping them somewhere else, a data folder on the server, a sheet, an atmosphere account, is a change to the first line:⟧
⟦// nothing else changes.⟧
