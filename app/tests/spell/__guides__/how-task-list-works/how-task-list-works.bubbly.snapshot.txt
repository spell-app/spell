==== /HowTaskListWorks.spell
⟪## How the Task List works⟫
⟦// The Task List example is a to-do list:  type a task, tick it off when it's done,⟧
⟦// and choose whether to see them all, only the ones to do, or only the ones done.⟧
⟦// Three ideas do the work:⟧
⟦// - each task is a THING of its own, which draws itself as a row with a checkbox⟧
⟦// - the list picks tasks out with "where":  "tasks in its tasks where it is active"⟧
⟦// - the list draws each task, or skips it, as its filter says⟧
⟦//⟧
⟦// This guide keeps those three, and leaves out dragging, selecting, the property editor,⟧
⟦// and where the tasks are kept:  here they're in memory, and start afresh each run.⟧
⟦// Open Task List, in the Examples, for all of it.  Lista de tareas is the same list, written in Spanish.⟧


⟪## A task⟫
[thing create_type L0]
| a «"task"» is a **view**
|   [property define_property_has L1]
|   | its «"title"» is **text**
|   [property define_property_has L1]
|   | its «"done"» is yes or no
|   [property quoted_type_expression L1]
|   | it «"is done"» if its **done** is _yes_    ‾value(its done)
|   [property quoted_type_expression L1]
|   | it «"is active"» if its **done** is _no_    ‾value(its done)

|   [action to_do_something L1]
|   | to **draw** it
|   |   ⟦// a form of its own, bound to the task:  ticking the box changes its "done"⟧
|   |   return <ui-form value={it}>    ‾value(<ui-form value={it}>)
|   |     <⟨ui-stack⟩ direction=«"horizontal"» spacing=«"sm"»>    ‾value(<ui-stack direction="horizontal" spacing="sm">)
|   |       <⟨ui-checkbox⟩ name=«"done"» aria-label=«"Done"»/>    ‾value(<ui-checkbox name="done" aria-label="Done"/>)
|   |       <⟨ui-text⟩>{its **title**}</⟨ui-text⟩>    ‾value(<ui-text>{its title}</ui-text>) code({its title})
|   |     </⟨ui-stack⟩>    ‾value(</ui-stack>)
|   |   </⟨ui-form⟩>    ‾value(</ui-form>)


⟪## The checklist:  the tasks, shown as its filter says⟫
[thing create_viewable_list_type L0]
| a «"checklist"» is a **viewable list of tasks**
|   [property define_property_has L1]
|   | its «"showing"» is one of ‹all›, ‹active› or ‹done›
|   |   ⟦// what it shows:  every task, the ones still to do, or the ones done⟧
|   [action draw_it L1]
|   | to **draw** each **item**
|   |   ⟦// each task in turn, unless the filter hides it:  "return nothing" draws nothing⟧
|   |   if its **showing** is _"active"_ and the **task** is done return nothing    ‾value(its showing) ‾question(the task is done) ‾value(nothing)
|   |   if its **showing** is _"done"_ and the **task** is active return nothing    ‾value(its showing) ‾question(the task is active) ‾value(nothing)
|   |   return draw the **task**    ‾value(the task)

[property belongs_to_one L0]
| a **task** belongs to one **checklist**


⟪## The app⟫
[thing create_one_of_a_kind L0]
| «task list» is an **app**
|   [property define_property_has L1]
|   | its «"tasks"» is **a new checklist**
|   [property property_value_getter L1]
|   | its «"active count"» is the **length** of (**tasks** in its **tasks** where it is active)
|   |   ⟦// how many are left:  the tasks picked out with "where", counted⟧

|   [action to_do_something L1]
|   | to **draw** it
|   |   return <ui-container text>    ‾value(<ui-container text>)
|   |     <⟨ui-menu⟩ appearance=«"secondary"»>    ‾value(<ui-menu appearance="secondary">)
|   |       <⟨ui-item⟩ kind=«"header"»>{its **active count** + _" to do"_}</⟨ui-item⟩>    ‾value(<ui-item kind="header">{its active count + " to do"}</ui-item>) code({its active count + " to do"})
|   |       <⟨ui-item⟩ selected={the **showing** of its **tasks** is _"all"_} onClick={set the **showing** of its **tasks** to _"all"_}>All</⟨ui-item⟩>    ‾value(<ui-item selected={the showing of its tasks is "all"} onClick={set the showing of its tasks to "all"}>All</ui-item>) code({the showing of its tasks is "all"}) code({set the showing of its tasks to "all"})
|   |       <⟨ui-item⟩ selected={the **showing** of its **tasks** is _"active"_} onClick={set the **showing** of its **tasks** to _"active"_}>To do</⟨ui-item⟩>    ‾value(<ui-item selected={the showing of its tasks is "active"} onClick={set the showing of its tasks to "active"}>To do</ui-item>) code({the showing of its tasks is "active"}) code({set the showing of its tasks to "active"})
|   |       <⟨ui-item⟩ selected={the **showing** of its **tasks** is _"done"_} onClick={set the **showing** of its **tasks** to _"done"_}>Done</⟨ui-item⟩>    ‾value(<ui-item selected={the showing of its tasks is "done"} onClick={set the showing of its tasks to "done"}>Done</ui-item>) code({the showing of its tasks is "done"}) code({set the showing of its tasks to "done"})
|   |     </⟨ui-menu⟩>    ‾value(</ui-menu>)
|   |     {draw its **tasks**}    ‾value({draw its tasks})
|   |   </⟨ui-container⟩>    ‾value(</ui-container>)

⟪## Where the example keeps its tasks⟫
⟦// This guide's tasks live in memory:  reload, and they start again.⟧
⟦// Task List keeps them, in one of four places the person picks from "Keep them in", above the list:⟧
⟦// - This browser, where it starts:  "browser storage is a database on this device"⟧
⟦// - A JSON file on the server, one file a task:  "task files is a data folder at "tasks""⟧
⟦// - A CSV file on the server, one row a task:  "task sheet is a sheet at "tasks.csv"", the project's own file⟧
⟦// - Your atmosphere account, Bluesky's AT Protocol, as Statusphere does:  "task sky is a personal atmosphere account"⟧
⟦//⟧
⟦// Each place is an API file of its own, and each holds a KEEPER with the same three things:⟧
⟦//       - its "kept tasks" is every browser task⟧
⟦//       - to keep a new task titled (title as text):⟧
⟦//           set task to a new browser task with title = title⟧
⟦//           add task to the browser tasks⟧
⟦//           return task⟧
⟦// and its kind of task says how one is thrown away:⟧
⟦//       a "browser task" is a task:⟧
⟦//           - it lives in browser storage⟧
⟦//           - to throw it away:⟧
⟦//               remove it from the browser tasks⟧
⟦//⟧
⟦// The app never names a place.  It asks its keeper:⟧
⟦//       for task in (the kept tasks of the keeper) sorted by its order⟧
⟦//       set task to keep a new task titled title of the keeper⟧
⟦//       throw the task away⟧
⟦// Picking another place in "Keep them in" changes its "storage";  "when its storage changes", the app takes that place's⟧
⟦// keeper, and fills the list from it.  A task kept anywhere saves itself as it changes:  there's no save step.⟧
⟦// Its place in the list is kept the same way, as its "order":  a drop sets each task's order to its place,⟧
⟦//       - when a task is dropped on it:⟧
⟦//           keep the order⟧
⟦// so the tasks come back in the order they were dragged into, whichever place keeps them.⟧
