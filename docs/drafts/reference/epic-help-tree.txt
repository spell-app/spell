##### epic --help
Usage: epic <verb> <epic>[#<id>] [arguments]

Work with epics:  their pages (epics/<name>/), the pages Owen answers on,
worktrees, sessions, windows, agents, airplane mode.

Options:
  -V, --version  the code this epic runs:  its commit, branch and checkout
  -h, --help     display help for command

Requests from other sessions:
  send           send an epic a request:  Owen's words and screenshots;  no
                 epic:  the tooling home
  requests       every request sent to an epic, and where each went
  file           file a request into a phase:  Owen's words and screenshots into
                 its Requests field;  or, with no phase, mark where it went:
                 "dropped:  done in P3"
  home           the tooling home, the epic dev-tooling requests go to;  with an
                 epic, set it
  merge          a standing epic's phase onto main at once, fast-forward only;
                 run in the main checkout

Epic page:  making and reading:
  create         make an epic page from the template;  --future:  an idea for
                 later, not planned yet;  --saga:  the saga it serves
  list           every epic:  in progress, future or done, where it runs, items
                 not reviewed
  summary        an epic's phases, the next one, its open questions, issues,
                 caveats and todos
  summaries      `summary --json` of each page, by path (worktrees' too), for
                 /epics
  items          what a review walks:  sections, counts, items, the queue
  docs           the docs an epic wrote besides its page, and its changelog
                 entry (for /docs-check)
  decisions      what an epic's page settled:  phases' Done and Updated notes,
                 items' answers
  open           show an epic's page in VS Code's side bar:  Spell Docs, or with
                 --review the Review tab
  lint           ids, #id links, phases, parts;  its links;  then the browser
                 check

Epic page:  phases:
  add-phase      add a phase:  what's wrong (symptom), what changes;  --before N
                 inserts it as PN
  update         set a phase's or an item's fields, or the page's flags;  or
                 Claude's status card on an item:  underway (spinner on), done,
                 or noted
  updated        a change to a phase's plan:  an Update block at the end of its
                 description
  phase          set a phase's status;  done:  --done writes what was built
  commit         list a commit under a phase or an item (replacing its entry
                 there)
  commits        every phase and item commit in the page's history, into their
                 lists

Epic page:  items:
  add            add an item (J judgement, Q question, I issue, C caveat, T
                 todo, V test, D decision)
  calm           items not urgent (yellow), as the page's id chip does;  --loud:
                 urgent (red) again
  decide         answer a question:  the answer goes into it;  --option marks
                 the chosen option
  choose         an option Owen settled in conversation, on ANY item, recorded
                 as the page's pick does:  chosen on its latest card set (--set
                 N:  the Nth), the item answered / closed / reviewed, a Noted
                 card
  close          close an item:  done
  reopen         open a closed or canceled item again
  cancel         an item made moot by another decision:  struck through
  details        write an agent's details or reply into an item;  --append adds
                 it, --more under it
  summarize      condense an item after a lot of back and forth:  the file
                 replaces what it shows;  its text and every reply move into its
                 Original Discussion, folded;  Owen's picks and the answer stay
  restore        put earlier text (from git) into an item's Original Discussion
  review         mark an item reviewed today;  the outcome goes in the log
  defer          put an item off:  still not reviewed, dated
  queue          work a review decided on, waiting to be done
  unqueue        off the to-do list:  started, or dropped

Epic page:  the review inbox:
  inbox          the marks and comments Owen sends from the page, and how a
                 review session takes them
  test           Owen's test run:  the page in the Review tab, one test at a
                 time, answered on the page;  --all:  every epic's;  --list:
                 the open tests

Epic page:  log and upkeep:
  log            a timestamped line in the page's log
  prompt         set the prompt that started the epic ("" removes it)
  bedtime        a /bedtime run:  start turns bedtime mode on (changes stay
                 green until reviewed), done off
  backfill       items Owen already went through in past sessions:  a dry run
                 unless --apply
  split          store a page as a skeleton plus part files;  --done:  every
                 finished epic
  join           a split page back into one file
  migrate        bring pages up to today's markup, every step of their kind;
                 safe to run again

Sagas:
  saga           the sagas (epics of epics):  their list in order, and the saga
                 each epic serves

Worktrees, sessions and parked work:
  worktree       git worktrees:  the live sessions and where they work, where a
                 name stands, merging main in
  session        Claude Code sessions:  list, find, open in VS Code, title this
                 one, mark finished ones ✅, digest a transcript
  park           parked work:  the PARKED notes, what /wait-for could wait on,
                 waiting for a name to finish
  status         take stock:  worktrees, branches, sessions, parked work, plans
                 -- in process, hung or parked, dead

Shared content:
  shared         shared content:  docs pages, sagas and logs in the content
                 folder, a repo beside the checkout, read from there;  a
                 checkout links in only the folders its config names
                 (sharedFolders)

Windows and the page server:
  window         VS Code windows per package and worktree:  open, close,
                 handoff, show, should-stay ...
  server         this checkout's page server;  start --all:  every web server
                 (page server, editor, Spell UI)
  hub            the machine's ONE epic server:  every registered repo's pages,
                 the engine's assets, the epic routes
  pages          the docs pages:  the home and list pages (index), a new page, a
                 page's links, opening one, its writing
  repo           the repos the epic server serves (~/.spell-epic/repos.json5):
                 add, list, remove, default

The repo's settings:
  config         where this repo keeps its epic things (.epic/config.json5):  a
                 value, or all of them
  init           set this repo up for epics:  its .epic/config.json5, the
                 content repo beside it, the links and their .gitignore lines;
                 safe to run again

Pages Owen answers on, agents, airplane mode:
  ask            details pages:  a question explained on a page in VS Code's
                 side bar, Owen answering on it
  choices        choice pages:  a table of names Claude recommends, Owen's call
                 on each
  comments       comments Owen leaves on docs pages:  list, wait for, gather,
                 mark and answer them
  notes          page notes Owen left on docs pages (before comments):  list,
                 answer, mark done
  agents         the running-agents list of this epic (else this checkout):
                 what each background agent is doing
  airplane       airplane mode:  the docs worked on with no Claude, everything
                 kept for /airplane land

Commands:
  help           show help -- for one verb, e.g. epic help update

Naming what a verb acts on:
  seo                 the epic's page, epics/seo/seo.plan.html
  seo#J3              an item:  J3 (a comment on the page, seo#M3, too;  m3, cm3 read the same)
  seo#P3              a phase:  P3, or by its id, seo#p-epic-migrate;  phase, updated and file take its name
                      too:  seo#epic-migrate, "seo#Epic Migrate"
  seo#J               a new item of that kind, for add:  epic add seo#J "Title"
  SAGA:/epics         a saga's page, sagas/epics/epics.saga.html:  epic add SAGA:/epics#T "Title"
  guides/x.html#M3    a comment on a docs page, for epic comments (and a page note, guides/x.html#n3)

Examples:
  epic summary seo
  epic phase seo#P3 done --done "<ul><li>...</li></ul>"
  epic update seo#P3 --goal "<p>...</p>" --estimate 2h
  epic update seo#J3 underway "Writing the answer"
  epic inbox wait seo

epic <verb> --help says more about each;  an id always goes after a #, never as a word of its own.

##### epic update --help
Usage: epic update <epic>#P3 | <epic>#J3 | <epic>  --field <value> ...  |  <epic>#J3 underway | done | noted ["<html>"]

set a phase's or an item's fields, or the page's flags;  or Claude's status card
on an item:  underway (spinner on), done, or noted

Options:
  -h, --help  display help for command

A phase (seo#P3):
  --symptom, --changes, --goal, --files, --verify <html>   its body ("" removes one)
  --estimate <time>                                       its estimate, e.g. 1-2h
  --title "New name" [--html]                             rename it:  links that say the old name follow
An item (seo#J3):
  --title "New title" [--html]                            retitle it
  --calm  /  --loud                                       not urgent (yellow)  /  urgent (red)
The page (seo):
  --standing [on | off],  --no-standing                   a standing epic:  open for good, never done
Claude's status card on an item (seo#J3;  an Overview sub-section seo#o3, a phase seo#P3, seo#summary), a state
word after the target, never with fields:
  underway "<reading>"                                    a blue card:  what Claude took the task to be;  spinner on
  done ["<summary>"]                                      WORK was done:  that card green, the summary under it
  noted "<what>"                                          Claude only RECORDED Owen's choice:  a calm Noted card

Examples:
  epic update seo#P3 --goal "<p>...</p>" --estimate 2h
  epic update seo#J3 --title "Clearer title"
  epic update epic-workflow --standing
  epic update seo#J3 underway "Reading the routes"
  epic update seo#J3 done "Answered;  one test skipped"

##### epic add --help
Usage: epic add <epic>#J "Title" [--details <html>] [--calm]  |  <epic>#V "Title" --step <html> --should <html> ...

add an item (J judgement, Q question, I issue, C caveat, T todo, V test, D
decision)

Options:
  -h, --help  display help for command

Prints the new item's id.  The letter after # is its kind:
  J judgement   Q question   I issue   C caveat   T todo   V test (checked by hand)   D decision (a question born answered)
--calm (last):  a judgement or issue that wouldn't surprise Owen, yellow rather than red.
A test (V) Owen's test run steps him through, its fields HTML (epic details seo#V3 takes them too):
  --step <html>       exactly what to do;  <a class="epic-test-action" href="...">Open ...</a> is a button in the run
  --should <html>     what should happen
  --example <png>     a screenshot of it, copied to tests/<id>.png beside the page;  or a line of text
  --if-not <html>     what to tell Claude when it doesn't

Examples:
  epic add seo#J "Kept one file per template" --details "<p>Why ...</p>" --calm
  epic add seo#V "The sitemap lists every page" --step "Open /sitemap.xml" --should "Every guide is in it"
