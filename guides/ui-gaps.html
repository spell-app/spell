Pages with Spell UI

 The same button, in old words and today's · 2 lines 
<ui-button primary basic compact href="save.html">Save</ui-button>
<ui-button color="primary" appearance="basic" padding="compact" link="save.html">Save</ui-button>

Every Spell UI tag says one idea with one word. And a page can be written without a single native HTML tag: tables, paragraphs, links, layout, video and the page itself are Spell UI tags.

A Spell drawing holds no native HTML, so whatever HTML could draw and Spell UI couldn't would be a gap. This page is the tour of what a page written from <ui-*> tags has: the words, the tags, showing a file and saving it back, and a plain-HTML copy of the page for search engines.

Written for: someone writing a page or a drawing with Spell UI's tags Each tag's own attributes, events and examples: its components page
  • One word per idea, on every tag: color, appearance, padding, spacing, direction, align, attach, length, selected, open, label, badge, heading, link, selector.
  • Attributes every tag takes: link and target, font, shadow, width and height (and their min and max), tooltip, label, movable, resizable, on-platform.
  • Tags for what a page needs with no native HTML: table rows and cells, stack, text with paragraphs, link, quote, keys, page, video and audio, terms, and an image's caption.
  • Three tags show a file: <ui-include> another page, <ui-code> code, <ui-markdown> Markdown; each can save it back.
  • Toolbars that fit their row, zoom, a textarea that grows, the page's contents and live examples are tags or attributes of their own.
  • spell ssr page.html writes a plain-HTML copy of the page, for search engines and readers with JavaScript off.
  • spell ui rename rewrites markup written in the old words: the old names no longer do anything on a page.
  • No drawing surface (shapes, a canvas, charts): the one large gap, set aside for later.

Fomantic UI, whose vocabulary Spell UI keeps, gave each look a bare switch of its own: <ui-button primary basic>. That made a dozen spellings of one idea across tags. In Spell UI each idea is one attribute, and the old switch is one of its values.

  • Each tag's components page lists its words on its API tab, with the old ones each replaced. Coming from Fomantic or Semantic UI: the migrating README.
  • Fomantic's classes didn't change, so nothing looks different: a primary colour still draws ui primary button in the shadow root.
link, font, tooltip, label and width · 5 lines 
Read <ui-text link="rules.html">the rules</ui-text> first.
It's <ui-text font="bold italic">free</ui-text>:  run <ui-text font="code">spell</ui-text>.
<ui-card link="game.html" tooltip="Start a game">...</ui-card>
<ui-icon name="trash" label="Delete"></ui-icon>
<ui-segment id="notes" width="24em" max-height="60vh" movable resizable="height">...</ui-segment>
  • link and target: on text, a real link you reach with Tab. On a tag that draws no link of its own, a click goes there.
  • font takes eight words, several at once: bold, italic, underline, strikethrough, code, highlight, subscript, superscript. Inside text, each draws its HTML element, so a screen reader hears it; on any other tag, the look alone.
  • shadow: a hard shadow behind its letters in a hue, shadow="yellow", a sticker's look for a logo or a title.
  • width, height, and each one's min- and max-: any CSS length. In a row a width is kept, never squeezed; height="fluid" takes what's left of its parent's height. A family with a width of its own keeps it (a column counts columns).
  • tooltip: the browser's own tooltip, written as the element's title.
  • label: the accessible name, where the family has no label of its own.
  • movable: people can drag it inside its container (bare, horizontally or vertically). resizable: they can drag its corner, the sizes it names. With an id, where each person put it, and the size, is remembered.
  • on-platform="desktop, tablet": shown only on those devices, following a resize or a turn at once.
  • In Spanish: enlace, destino, letra, ayuda, etiqueta ...
 spell ui rename · 2 lines 
spell ui rename docs/            # a dry run:  lists each file and what it would change
spell ui rename --write docs/    # rewrites them
  • It reads every old name from the vocabularies themselves, so it keeps no list of its own.
  • It rewrites HTML pages, Markdown, .spell files, CSS selectors and the JSX in TypeScript files: whole tags too (<ui-docs-toc> becomes <ui-toc>).
  • Several old switches on one tag become one appearance.
  • It lists what it can't see, a JSX expression or a tag it can't read, and never guesses.
  • --markup-only leaves escaped markup alone, for pages that quote old names on purpose.
  • A dry run exits 1 when there's something to change.
  • <ui-breadcrumbs> is the trail, and <ui-breadcrumb> one step.
  • Floated is gone from ten tags: a stack places things left and right instead.
  • <ui-image floated="left"> stays: text wraps round an image, which no stack can do.

Each tag below is written <ui-stack> on a page, and <stack> in a Spell drawing. Each has a components page with its every attribute, its Spanish name and its tests.

A table of rows and cells · 9 lines 
<ui-table celled appearance="striped" client-sort caption="Scores">
  <ui-row header>
    <ui-cell>Player</ui-cell><ui-cell>Score</ui-cell>
  </ui-row>
  <ui-row>
    <ui-cell header>Ann</ui-cell><ui-cell align="right">12</ui-cell>
  </ui-row>
  <ui-row footer><ui-cell span="2">One player</ui-cell></ui-row>
</ui-table>
  • A row with header is the header row; a cell with header is its row's own header.
  • Every table look works as on a native table: celled, striped, padding, selectable, inverted, a colour. It stacks at phone width.
  • Screen readers hear a real table, named by its caption. Sorting moves the row elements.
  • <ui-row> is also the grid's row: in a table it's a table row, in a grid a grid row.
  • The catch: a cell covers columns (span), never rows. A caption draws inside the table's border. Its page: <ui-table>.
A row of buttons, and one at each end · 7 lines 
<ui-stack direction="horizontal" wrap spacing="sm">
  <ui-button>New game</ui-button>
  <ui-button>Undo</ui-button>
</ui-stack>
<ui-stack direction="horizontal" justify="between">
  <ui-header>Solitaire</ui-header><ui-button>Deal</ui-button>
</ui-stack>
  • A column by default; a horizontal one is a row, and wrap lets it wrap.
  • spacing: none to xl, md (1em) by default.
  • align lines children up across it: start, center, end, stretch, baseline.
  • justify places them along it: start, center, end, between, around.
  • fluid takes the full width. No padding, border or colour of its own.
  • Its page: <ui-stack>.
Running text · 7 lines 
<ui-text paragraph>
  You have 12 points.  Read <ui-link link="rules.html">the rules</ui-link>, then press Deal.
</ui-text>
<ui-quote cite="https://example.com/ada">Imagination is the discovering faculty.</ui-quote>
She said <ui-quote inline>go</ui-quote>.
Save with <ui-keys shortcut="mod+S"></ui-keys>.
<ui-keys shortcut="mod+S" platform="apple"></ui-keys>
  • paragraph on a text makes it a paragraph.
  • A quote is a block, or a phrase with inline; cite says where it's from.
  • <ui-keys> draws a shortcut as key caps, mod as ⌘ on a Mac and Ctrl elsewhere, unless platform says which.
  • Their pages: <ui-text> (the link is a section of it), <ui-quote>, <ui-keys>.
A whole window · 7 lines 
<ui-page>
  <ui-header slot="header" level="1">Solitaire</ui-header>
  <ui-menu slot="nav" direction="vertical">...</ui-menu>
  <ui-stack>... the game ...</ui-stack>
  <ui-card slot="aside" heading="Best scores"></ui-card>
  <ui-text slot="footer">Made with Spell</ui-text>
</ui-page>
  • Its slots are the landmarks screen readers jump between: header, nav, aside, footer. What has no slot is the main content.
  • A Skip to content link comes first, shown only while it has the keyboard's focus.
  • It's a root too, like <ui-root>: it loads what's inside it, and paints the window's background. With no theme set, it follows the system's light or dark.
  • One per page. On a narrow screen, the nav and aside stack above and below the content.
  • Its page: <ui-page>.
A video, and a sound played on a click · 3 lines 
<ui-video src="intro.mp4" poster="intro.jpg" captions="intro.vtt" ratio="16/9"></ui-video>
<ui-audio id="deal" src="deal.mp3"></ui-audio>
<ui-button onclick="document.getElementById('deal').play()">Deal</ui-button>
  • The browser's own players, each file relative to the page: keyboard, full screen and captions work.
  • A video shows its controls unless controls="false".
  • Without controls, an audio shows nothing: for a game's sounds.
  • From script: play(), pause() and currentTime; events: ui-play, ui-pause and ui-ended.
  • Autoplay plays only when muted, or after the reader has clicked: browsers allow nothing else. Its page: <ui-video>.
A card's details · 4 lines 
<ui-terms>
  <ui-term label="Suit" value="hearts"></ui-term>
  <ui-term label="Owner"><ui-link link="ann.html">Ann</ui-link></ui-term>
</ui-terms>
  • Labels in one column, values in the next, lined up; horizontal puts the pairs in a row.
  • A value can be anything inside the term; a label slot holds a label with markup.
  • Screen readers hear term and definition. Its page: <ui-terms>.
caption · 1 line 
<ui-image src="deck.png" caption="The deck"></ui-image>
  • With a caption it draws a figure and its caption, so screen readers tie the two.
  • A caption slot holds one with markup; an image without one draws as before.
  • Its page: <ui-image>.
Another page's part, a file of code, a Markdown file · 3 lines 
<ui-include source="/docs/part.html" selector="#release">Loading the release notes...</ui-include>
<ui-code language="ts" source="example.ts" line-numbers copy></ui-code>
<ui-markdown source="notes.md" heading-offset="2"></ui-markdown>
  • Three tags show a text file:
    • <ui-include> shows another page of the site, or its part a selector matches
    • <ui-code> shows highlighted code
    • <ui-markdown> shows GitHub-flavoured Markdown
  • Each takes a source on the same site, or its own text written inside it (<script type="text/plain"> keeps it exact). Each shows a loading and an error state.
  • An included page goes in its own shadow root, so page CSS stays out and Spell UI's tokens still apply; page-styles puts it in the page instead. Its scripts don't run.
  • The engines load only when a page shows code or Markdown: highlight.js, marked, and DOMPurify too with sanitized. A Spell block is coloured where the page has registered Spell's highlighter, as Spell's own pages do.
  • To save one: change its content, then save(). The page decides where it goes:
    • it registers a saver, UI.sources.saver, which Spell UI doesn't ship;
    • or it cancels the element's ui-save event and saves the text itself.
  • On Spell's page server, pages save their text files in place. Each save is checked against the file's version, so a file changed underneath is a conflict, not lost work.
  • Their pages: <ui-include>, <ui-code>, <ui-markdown>; how loading and saving work inside: the runtime README.
A toolbar that fits its row · 4 lines 
<ui-toolbar shrinkable>
  <ui-item icon="question">Questions <ui-label slot="badge">3</ui-label></ui-item>
  <ui-item>Todos</ui-item>
</ui-toolbar>

Make the row narrower, and it gives way in four steps:

  1. Every title whole, while they fit.
  2. The longest titles are cut first, each ending in "…".
  3. Once a title would be cut under 50px, the whole row shows icons only. An item with no icon shows its title's first letter, and each title becomes its item's tooltip.
  4. Once even an icon button would be under 34px, every item folds into one "…" button, whose menu holds them all. A dot on it says an item inside has a count.
  • A segmented menu doesn't cut its titles: once a choice wouldn't fit, it becomes one button showing the chosen item, opening the same choices.
  • Two tokens set the steps: --ui-menu-title-min (50px) and --ui-menu-item-min (34px).
  • A count that must stay goes in the item's badge slot.
  • Without shrinkable, a toolbar scrolls with ‹ › as before.
 Anything, shown shrunk, then full size · 4 lines 
<ui-zoom max-width="320px" shrink="50%">
  <ui-table>...</ui-table>
</ui-zoom>
<ui-image src="board.png" alt="The board" zoom></ui-image>
  • <ui-zoom> shows what it wraps at half size by default: shrink sets how small, max-width and max-height cut it off.
  • A click shows it full size, over the page; Escape, a click outside or its close button close it.
  • <ui-image zoom> is a button: a click (or Enter) shows the image full size.
  • Plain screenshots open full size on any page that loads Spell UI: an <img> shown smaller than it really is, no markup needed.
grow · 1 line 
<ui-textarea grow max-rows="8" placeholder="Tell me more"></ui-textarea>
  • It starts one line tall, and grows a line as the text wraps.
  • At max-rows it stops and scrolls; without it, at a third of the window.
  • It gets shorter again as text goes.
 A page's contents, and one live example · 4 lines 
<ui-toc heading="Buttons"></ui-toc>
<ui-example heading="Emphasis" description="A primary button is the page's main action.">
  <ui-button color="primary">Save</ui-button>
</ui-example>
  • <ui-toc> lists the page's sections and examples as links, opens the one in view and follows the scroll. Each section folds, and the reader's folds are kept.
  • <ui-example> shows its markup live, under a heading and description, with a button that shows the same markup as code.
  • Spanish: <es-indice>, <es-ejemplo>.
 Drawing a README's examples · 1 line 
spell readme pictures README.md    # each html example block, drawn light and dark
  • GitHub runs no custom elements, so a README can't show a live example. Instead, spell readme pictures draws each html example block headlessly, light and dark, and puts the picture under it.
  • spell readme check fails a picture older than its markup.

Search engines, link previews and readers with JavaScript off get the same page, as plain HTML: no shadow DOM, no script. It looks the same, and its links and forms work.

  • spell ssr page.html writes page.static.html beside it, and the folder's shared stylesheet, ui.static.css, which holds only the families its pages use, minified.
    • Each element becomes its rendered HTML: a card an article, a modal a real dialog.

    • Rendering one page again never drops another's styles from the stylesheet.
  • It never overwrites a page: an output naming an input is refused.

What works without JavaScript

Family With JavaScript off How
modal, flyout, page dimmer opens, closes a native dialog; its buttons get the browser's own commands
click popup opens a native popover
accordion works <details>
forms: input, textarea, checkbox, radio, select, dropdown, slider, rating, calendar, search submit native controls carry their name and value; a submit button is a real one
sticky, progress, reveal works CSS
sidebar overlay only a native dialog; push and uncover need JavaScript
dropdown menu opens choosing needs JavaScript
tabs the selected pane the other panes are in the HTML, hidden
hover or focus popup read, not shown a hidden tooltip a screen reader reads
search, shape, slider, element dimmer static first state only
  • Spell UI's commands become the browser's own: --show becomes show-modal, so a button opens its dialog with no script at all.
  • Generated ids skip the page's own.
  • The catch: open popups, modals and flyouts render closed. And the static page must never load the elements as well: they'd take the rendered HTML for their content and show it twice.
  • 55 of the 62 families render; the rest stay as they are and are listed: ui-code, ui-markdown, ui-include, ui-panel, ui-property-editor, ui-tree-diagram, ui-components.
  • The cost is the stylesheet, most of it the foundation: a page with one button gets 143 kB minified (20 kB gzipped).
  • The same render from your own node code is the SSR namespace, spell/ui/static; serving the files from Flask or Quart: the runtime README, "The static render".
  • No drawing surface yet: shapes, a canvas, charts. Maybe it's just SVG and its own tags; that's for later.
  • A page still in the old names draws them as if they weren't there: run spell ui rename.
  • A link on a tag that draws no link of its own (a segment) is a click only: no Tab stop, no middle-click, no link role. A real link is text with a link, or the link tag.
  • Font's highlight, subscript and superscript show only inside text.
  • Table cells span columns, never rows.
  • Video and audio look like the browser's players, not Spell UI.
  • Fitting titles is checked in Chromium only: its steps are CSS style queries, untried in Firefox and Safari.
  • The "…" button's "More" is read once: a page that turns Spanish after the menu draws keeps "More".
  • A growing textarea doesn't measure again when only its width changes.
  • <ui-zoom open> set from script keeps no room in the page while it's open.
  • spell ui rename leaves a few lines for a person: JSX values it can't see, and a button label that could be either.
