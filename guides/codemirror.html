The Editor

Every place Spell's editor shows code runs on CodeMirror 6: the code pane, the Inspector's Code card, the compiled pane, Publish's diff, notebook cells and <spell-editor>. Its chunk is 681 kB, loaded only once a program has compiled and run. This page is the editor as you work in it, and how it's built, then the property editors it makes and reads.

Written for: anyone changing how the editor app shows or edits code, or lays out a type's properties Checked: 2026-11-21, every file, command and menu item against that day's code The reference beside it: README-app, "The editor", and the app code's own AGENTS.md, "The app's CodeMirror plumbing"
  • The code editor is CodeMirror 6, with Spell's language service in the page: suggestions, hovers, problems, Go to Definition, Rename.
  • Spell's bubbly look is marks in the lines themselves, made only for the lines on screen. Every line is one height, 25px.
  • One CodeMirror view, a state per open file: switching files keeps each one's typing, undo, folds, caret and scroll.
  • Every word it shows can be Spanish: its 33 phrases are keys in the app's texts.
  • A property editor is a form Spell UI draws from a type's description. The editor writes one as a page, Card.editor.html; a type's Inspector layout lives in Card.editor.spell.
  • Not yet: <spell-editor> has no right-click menu.
  • Nine typing helps: indent after a tag or a block, Enter before a comment, Enter between a tag's attributes lining up under the first, a paste taking the indent where it lands, Shift+Tab / ⌘[ / ⌘] moving the lines under, the caret snapping into a blank line's body, closing quotes and tags.
  • A curly brace or a quote switches a value between code and text: typing { in color="blue" makes it color={blue}.
  • Each help is one undo step, and only the editor you type in helps.
  • |> typed in a tag writes />.
  • A comment's double dash, drawn as one dash, is one step for the caret, and Backspace takes both.
  • The popups that show by themselves wait for typing to pause, as long as Settings… › "Delay before showing help" says: Short 0.4 s, Standard 0.8 s, Long 1.5 s. Ctrl+Space shows them at once.
  • Accents are fixed as you type: numero becomes número.
  • Suggestions, in the language service's order; hover (⌥ shows it, as Settings… says); problems.
  • Go to Definition (F12), Find All References (⇧F12), Rename Symbol (F2), type definition, signature help.
  • Go to Definition on a Spell UI tag shows the tag's help.
  • Peek Definition (⌥F12) and Peek References (⇧⌥F12): a box under the line shows the other place, read only and drawn bubbly; Enter goes there, Esc closes it.
  • Format Document, expand and shrink selection, Go to Symbol (⇧⌘O).
  • The value picker and value choices under an attribute (colours, icons), link icons with ⌘-click, comment headings.
  • Pinned lines (Settings… › Pinned lines): the tags you're inside stay at the top as you scroll.
  • The right-click menu is the app's own menu popup, the Palette's, its shortcuts from the editor's one hotkey list.
  • A file parses 200 ms after typing stops, and saves by itself.
  • ⌘Z asks the file's own history first, then the app's.
  • No line numbers unless View › Line Numbers turns them on; fold arrows show over the code's left padding while the mouse is there.
  • ⌘F opens a find bar like VS Code's: Aa / ab / .* in the field, a match count, a Replace row that stays folded once you fold it.
  • Four clicks select the block a line is in, each click after that the block around it.
  • CSS files and property editors files (Card.editor.spell) are coloured too.

/demo/codemirror.html, on the editor's dev server, shows every look on one page: a Spell file, an HTML page, the look off, a slice, both sides of a diff, the compiled code.

  • ?lang=es: in Spanish
  • ?project=: another project's files
  • ?highlights=on: the highlights, off in the app
  • Drawn bubbly, every line is 25px: a block's feet are drawn over the blank line under it, else along the bottom of its last line.
  • So CodeMirror's guess at the height of lines it hasn't drawn is always right, and scrolling never changes the file's height.
  • A description too wide for its band is cut short with …, its whole text in a tooltip.
  • The layout is worked out for the whole file; the bubbly marks are made only for the lines CodeMirror draws, again as you scroll (CodeMirrorRelayout).
  • A keystroke in a 2,668-line file took 68 ms, measured on 2026-11-19; it was 157 before.
  • Until its project's parse is in, a file is drawn from its text alone, with the same blocks and bands.
  • FileStates keeps one CodeMirror state per open file: its text, undo, folds and selection.
  • The code pane is ONE view showing each file's state in turn.
  • The Inspector's slices and the diff read the same state, so an edit anywhere is an edit everywhere.
  • An outside edit (the side bar, Rename, the value picker) goes through it as one undo step.

What's Spell's, not an editor's, lives once, where VS Code's extension can read it too:

  • the typing rules, LSP.SpellTyping
  • spell: file addresses, LSP.AppAddresses
  • what a hover says and which code actions show, CodeEditorFeatures
  • the one colour table, from token to --ui-code-* colour, CodeRules
  • the value popups' drawing, ValuePopups

The CodeMirror side is thin wiring over them, a file per feature (CodeMirrorTyping, CodeMirrorHovers ...), and one converter of the language service's answers, LspToCodeMirror.

  • CodeMirror loads after the program compiles and runs, never in the main bundle: LazyCodeMirror.
  • <spell-editor> has its own lazy chunk, which must not bring the editor page with it.

A property editor is a form Spell UI draws from a description of a thing: groups, and a field per property with its label, tip, choices and rules. In a hand-built form each field repeats them; here the markup says only how this one form lays them out. The elements themselves are Spell UI's: <ui-property-editor>, <ui-property-group>, <ui-property>.

  • A layout can live in a page of its own, Card.editor.html: plain markup, loaded as it is by <ui-property-editor source="Card.editor.html">.
  • The page holds only the layout: groups, order, controls, hints. Everything else comes from the type.
  • The editor's file menu writes one: New Property Editor…, then pick a template. It never writes over a page; a second one is Card2.editor.html.
  • spell lint checks every *.editor.html in a project against its types as they are now: a property the type dropped, one the page doesn't place, a control that no longer fits. spell lint --fix mends what it can.
  • spell compile turns each one into a module defining <card-editor>, its layout and the type's schema inlined, importing only Spell UI's property editor (PropertyEditorPages). 
<property-editor "card">
	<ui-property-group label="Card" columns="2">
		<ui-property name="rank" label="Rank" />
		<ui-property name="suit" label="Suit" as="buttons" width="16" />
		<ui-property name="direction" label="Face" as="buttons" />
	</ui-property-group>
	...
</property-editor>
  • Solitaire's card lays out its Inspector card in Card.editor.spell.
  • One type's in <Type>.editor.spell, or any of the project's types' in <Project>.editors.spell.
  • The Inspector reads it; it's never compiled into the program.
  • It isn't an editor page: New Property Editor… writes those.
  • The editor's Project Settings opens a dialog, "<title> settings", drawn by a property editor: ProjectSettings.tsx.
  • It edits the project file, held until Save: its title, its version, the languages it also compiles to, and where lists start, 1 or 0.
  • It shows the Spell the project was written for, read only.
  • Saving writes them into the project file, keeping its imports and comments.
  • <spell-editor> has no right-click menu and no Find All References. The app's menu can't load on a page holding only that element; Go to Definition, Rename, Find and Undo work there.
  • In a diff, a gap for inserted lines cuts the rails on the other side.
  • With line numbers on, or scrolled sideways, a band with a description is off by their width.
  • A pinned line not drawn yet is pinned as plain text; at most 5 are pinned.
  • Go to Symbol lists what the file declares by each line's text, not as a nested outline.
  • Go to Definition on a Spell UI tag shows its help from the second press, the first time: its table loads on the first ask.
  • A property editor's labels from a Spell type are its property names, in English.
