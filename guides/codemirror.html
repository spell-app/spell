CodeMirror in Spell's Editor

Every place Spell's editor app shows code runs on CodeMirror 6, and Monaco is gone from the repo: the editor's lazy chunk went from 4.6 MB to 687 kB.

Written for: anyone changing how the editor app shows or edits code Status: built, merged into main The record: epic codemirror's page Branch: codemirror, merged 2026-11-16, its fixes through 2026-11-19

It looks the same as before, on purpose: the bubbly look, the typing helps and the language features came over one by one, each checked against Monaco side by side before Monaco went.

  • Where: the code pane, the Inspector's Code card, the compiled pane, Publish's diff, notebook cells, and <spell-editor>.
  • Why: a sixth of Monaco's size, Solitaire drawn bubbly in 226 ms instead of 686, and every word the editor shows can be Spanish; Monaco's stayed English.
  • Since the swap: a peek view, a compact find bar, every line one height, and the bubbly marks made only for the lines on screen: a keystroke in a 2,668-line file 68 ms, was 157.
  • Not yet: <spell-editor>'s right-click menu (see Limits).

Nothing to learn if you used the editor before: the keys, menus and settings are the same ones.

  • All nine typing helps: indent after a tag or a block, Enter before a comment, Enter between a tag's attributes lining up under the first, a paste taking the indent where it lands, Shift+Tab / ⌘[ / ⌘] moving the lines under, the caret snapping into a blank line's body, closing quotes and tags.
  • A curly brace or a quote switches a value between code and text. Typing { in color="blue" makes it color={blue}.
  • Each help is one undo step, and only the editor you type in helps.
  • |> typed in a tag writes />.
  • A comment's double dash, drawn as one dash, is one step for the caret, and Backspace takes both.
  • The popups that show by themselves (suggestions, signature help, hovers) wait for typing to pause, as long as Settings… › "Delay before showing help" says: Short 0.4 s, Standard 0.8 s, Long 1.5 s. Ctrl+Space shows them at once.
  • Accent fixes as you type (numero becomes número).
  • Suggestions, in the language service's order; hover (⌥ shows it, as Settings… says); problems.
  • Go to Definition (F12), Find All References (⇧F12), Rename Symbol (F2), type definition, signature help.
  • Go to Definition on a Spell UI tag shows the tag's help.
  • Peek Definition (⌥F12) and Peek References (⇧⌥F12): a box under the caret's line shows the other place, read only and drawn bubbly, the uses listed beside it; Enter goes there, Esc closes it.
  • Every Go to … jump scrolls the whole block it lands in into view, its head a row below the top.
  • Format Document, expand and shrink selection, Go to Symbol (⇧⌘O).
  • The value picker and value choices under an attribute (colours, icons), link icons with ⌘-click, comment headings.
  • Pinned lines (Settings… › Pinned lines): the tags you're inside stay at the top as you scroll.
  • The right-click menu is the app's own menu popup, the same one the Palette uses, its shortcuts from the editor's one hotkey list.
  • Switching files and back keeps each one's typing, undo, folds, caret and scroll.
  • A file parses 200 ms after typing stops, and saves by itself.
  • ⌘Z asks the editor's own history first, then the app's (the order the app already had).
  • No line numbers unless View › Line Numbers turns them on; fold arrows show over the code's left padding while the mouse is there, and a folded block's arrow always shows.
  • The compiled pane marks the line you're on with a 3px bar in the gutter.
  • ⌘F opens a find bar like VS Code's over the code's top right: Aa / ab / .* in the field, a match count, the Replace row showing until you fold it (it stays folded).
  • A press inside a selection starts a new one, as in VS Code with drag-and-drop off; four clicks select the block the line is in, each click after the block around it.
  • CSS files and property editors files (Card.editor.spell) are coloured too.

Find and replace, folds, suggestions, problems and the diff's arrows speak the app's language: each of CodeMirror's 33 phrases is a key in the app's texts, its Spanish loaded only on a Spanish page.

/demo/codemirror.html, on the editor's dev server, shows every look on one page: a Spell file, an HTML property editor page, the look off, a slice, both sides of a diff, the compiled code.

  • ?lang=es: in Spanish
  • ?project=: another project's files
  • ?highlights=on: the highlights, off in the app

Monaco drew Spell's bubbly look as a layer behind the text, kept lined up with it. In CodeMirror the look is marks in the lines themselves, so there's nothing to keep in step.

  • Drawn bubbly, every line is 25px: a block's feet are drawn over the blank line under it, else along the bottom of its last line, and a row of HTML end tags is one line tall.
  • So CodeMirror's guess at the height of lines it hasn't drawn is always right: scrolling Solitaire and Table's examples never changes the file's height (it changed 8 and 88 times before).
  • A description too wide for its band is cut short with …, its whole text in a tooltip.
  • The layout is worked out for the whole file, but the bubbly marks are made only for the lines CodeMirror draws, again as you scroll (CodeMirrorRelayout).
  • A keystroke in Table's examples (2,668 lines) takes 68 ms, was 157: the marks 25 ms for the file plus 4 ms on screen, were 115. Solitaire's screenshots are pixel-identical.
  • Still whole-file: each line's rails and heads, the hidden line breaks and the feet, since typing on a blank line moves them far from where they're read.
  • A file is drawn from its text alone until its project's parse is in, with the same blocks and bands: a line naming another file's type is read again with a stand-in for it.
  • FileStates keeps one CodeMirror state per open file: its text, undo, folds and selection.
  • The code pane is ONE view showing each file's state in turn, where Monaco's pane made an editor per file.
  • The Inspector's slices and the diff read the same state, so an edit anywhere is an edit everywhere.
  • An outside edit (the side bar, Rename, the value picker) goes through it as one undo step.

What's Spell's, not an editor's, lives once, where VS Code's extension can read it too:

  • the typing rules, LSP.SpellTyping, beside the keywords
  • spell: file addresses, LSP.AppAddresses
  • what a hover says and which code actions show, CodeEditorFeatures
  • the one colour table, CodeRules, from token to --ui-code-* colour
  • the value popups' drawing, ValuePopups

The CodeMirror side is a thin wiring over them, a file per feature, such as CodeMirrorTyping or CodeMirrorHovers. One converter turns the language service's answers into CodeMirror's: LspToCodeMirror.

CodeMirror loads after the parser compiles and the app runs, never in the main bundle (LazyCodeMirror). <spell-editor> has its own lazy chunk, which must not bring the editor page with it.

Until the last build step, CodeMirror ran only on the demo page; then every place moved at once and Monaco went, with no setting to pick between them.

It beat a View › Code Editor setting that would have let each step be tried in the real app. The catch: nothing to try in the app until late, and the integration page tests met the new editor all at once.

The gutter has no bar marking changed lines. It beat a bar against the published copy (what Publish would send), against the file as opened, and against the last save, which would flash and vanish as the app saves 2 s after typing.

FileStates started as its own copy of the editor-free half of Monaco's SpellModels (its parse and save waits, which project a file is in, outside edits).

It beat a base class both editors extend: less to move while both lived, at the cost of copying any change by hand; before Monaco went, SpellModels was checked, and had nothing newer to carry over.

Each file keeps CodeMirror's own history, and ⌘Z asks it before the app's, the order the app had with Monaco; it beat folding them into one history.

Its phrases are keys in the app's texts, with four rewordings (Diagnostics became Problems). It beat a separate table of CodeMirror's English, which would have been a second place to translate.

Find All References lists the uses in the right-click popup, a row each that goes there. The peek box came later, as its own plain-DOM widget under the line, so <spell-editor> has it too, where the app's menu can't load.

A block's feet used to take a row of their own, so lines were of many heights and the scroll bar jumped as CodeMirror measured them. Now they're drawn over the blank line under the block, and where there's none, along the bottom of the block's last line.

That beat two other ways to give them room: a row exactly one line tall where no blank line follows, which loosened nested code; and Format Document adding a blank line after every block, which asks for blank lines Spell's words don't need.

What doesn't work yet, or works differently from Monaco:

  • <spell-editor> has no right-click menu and no Find All References. The app's menu can't load on a page holding only that element; Go to Definition, Rename, Find and Undo work there.
  • The integration page tests aren't all settled: 13 of 189 still failed after the swap's fixes (was 48 of 186), among them Solitaire's foundations the side bar can't change any more.
  • In a diff, a gap for inserted lines cuts the rails on the other side.
  • A band with a description reaches the right edge by CSS, with a fixed 8px gutter: with line numbers on, or scrolled sideways, it's off by their width.
  • ⌥ with the mouse resting shows the hover after the popup delay, not at once.
  • A drag that ends in a head's comment row, under its band, ends in the head's words.
  • A pinned line not drawn yet is pinned as plain text, not bubbly; at most 5 are pinned.
  • Go to Symbol lists what the file declares by each line's text, not as a nested outline.
  • Go to Definition on a Spell UI tag shows its help from the second press, the first time: the help table loads on the first ask.
